# 동탄 걷기·운동 지도 — 설계 문서

작성일: 2026-11-01

## 1. 목적과 이유

- 사용자는 경기도 화성시 동탄구 일대를 **주로 도보로 이동하면서**, 삼성 안드로이드 휴대폰 브라우저(삼성 인터넷/크롬)로 주변의 산책로·런닝코스·자전거도로와 그 중간중간의 시민 휴게시설·운동시설을 확인하고 싶다.
- 데이터는 **온톨로지 기반 지식 DB**로 구성한다. 목적은 단순 저장이 아니라, 향후 이 DB를 **MCP 서버로 만들어 AI 챗봇이 "여울공원 근처 운동시설" 같은 관계를 질의·추론**하게 하는 것이다.
- 기본 구조가 완성되면 **여러 생활편의시설**(예: 화장실, 약국, 편의점 등)을 계속 추가할 예정이다.

## 2. 목표

1. 휴대폰 전용(모바일 우선) 지도 웹사이트.
2. 지도 중심: **경기도 화성시 동탄구 청계동 552**.
3. 범위: 중심에서 **반경 10km 미만**의 데이터만 포함.
4. **모든 위치 정보는 중심으로부터의 거리(km)** 를 속성으로 가진다.
5. 휴대폰 **현재 위치(GPS)** 표시, 그리고 각 장소의 **내 위치로부터의 거리** 표시.
6. 장소별 **"네이버 지도에서 열기/길찾기" 버튼**(키 불필요 URL 링크 방식).
7. 지식 DB는 RDF/OWL 온톨로지(Turtle `.ttl`)로, 생활편의시설 확장이 쉬운 계층 구조.

## 3. 비목표 (이번 범위 아님)

- MCP 서버, AI 챗봇 구현 (구조만 대비).
- 회원 가입·로그인·리뷰·사용자 등록 기능.
- 사이트 내 길찾기(경로 안내) 자체 구현 — 네이버 지도 앱으로 넘긴다.
- 생활편의시설 데이터 추가 (구조만 준비, 데이터는 다음 단계).

## 4. 반(反)목표 (기술적으로 돌아가도 실패로 보는 것)

- 장소 이름을 임의로 바꾸거나 지어내는 것. **장소 이름은 공공데이터 원본 이름 그대로** 쓴다.
- 출처를 알 수 없는 좌표·시설을 섞는 것.
- 휴대폰에서 한 손으로 쓰기 불편한 화면(작은 글씨, 데스크톱형 레이아웃).
- 사이트와 지식 DB의 데이터가 서로 어긋나는 것(원본은 하나여야 함).

## 5. 제약 조건 (사용자가 정한 것)

- **API 키를 사용할 수 없다.** → 네이버/구글/카카오 지도 JS API, 키가 필요한 공공데이터 Open API 모두 사용하지 않는다.
- 지도는 **OpenStreetMap**(키 없음) 사용. 지도 라이브러리는 Leaflet (빌더 판단 가능).
- 데이터 출처는 **공공데이터포털(data.go.kr) 등의 공공데이터 파일(CSV 등)** 우선, 부족한 부분은 OpenStreetMap 보충(10장 참고). 장소 이름은 데이터셋 원본 이름 그대로.
- 위치 기능을 위해 **HTTPS 배포 필수** → **GitHub Pages**, 계정 `romanryu-rgb` (gh CLI 로그인 확인됨).
- 모든 화면 문구와 사용자와의 대화는 **한국어**.

## 6. 화면 (사용자가 고른 A안)

- **지도 전체 화면 + 아래에서 끌어올리는 목록(bottom sheet)** — 네이버 지도 앱과 유사.
- **맨 위 분류 버튼은 아이콘만** 표시(글자 설명 없음): 전체 / 🚶 산책로 / 🏃 런닝코스 / 🚲 자전거도로 / 💪 운동시설 / 🪑 휴게시설 (생활편의시설 아이콘은 추후 추가). 아이콘 의미는 접근성 라벨(aria-label)로만 제공.
- 지도 위: 경로는 종류별 색 선, 시설은 종류별 마커, 중심(청계동 552) 표시, 내 위치 파란 점, "내 위치로" 버튼.
- 아래 목록: **내 주변 가까운 순** 정렬. 각 항목에 원본 이름, **나에게서 거리**, **중심에서 거리(km)**, 네이버 지도 버튼.
- 위치 권한을 거부/미지원 시: 중심 기준 거리 순으로 정렬하고 안내 문구 표시.
- **(사용자 결정) 현재 위치가 중심에서 10km 이상 떨어져 있으면 내 위치를 지도에 표시하지 않는다.** 이때는 GPS 없이 동탄구 중심 기준 지도로만 검색·탐색하게 하고, "나에게서 거리"는 숨기고 중심 기준 거리 순으로 정렬한다. 걷다가 10km 안으로 들어오면 자동으로 내 위치 표시로 전환.
- **(사용자 결정) PC 접속도 같은 규칙.** PC는 위치 파악이 안 되거나 부정확하므로, 위치를 얻지 못하면(권한 거부·미지원·시간 초과) 지도 중심(청계동 552) 기준으로 보여 준다. 위치를 얻었더라도 10km 이상이면 위와 동일하게 표시하지 않는다. PC 화면에서도 깨지지 않게 표시(같은 A안 구성, 넓은 화면에서는 목록 패널 폭 제한 정도로 충분).
- 항목/마커를 누르면 상세(분류, 주소, 출처 데이터셋명·기준일, 주변 관계: 근처 시설, 속한 공원, 경로 위 시설 등).

## 7. 지식 DB (온톨로지)

### 7.1 형식
- RDF/OWL, Turtle(`.ttl`). 스키마(온톨로지)와 인스턴스 데이터 파일 분리.
- 좌표는 GeoSPARQL(`geo:hasGeometry`, WKT) 또는 WGS84 위도/경도 — 빌더 판단. MCP 단계에서 SPARQL로 질의 가능해야 한다.

### 7.2 클래스 계층 (최소)
```
장소(Place)
├─ 경로(Route)
│   ├─ 산책로(WalkingTrail)
│   ├─ 런닝코스(RunningCourse)
│   └─ 자전거도로(BikePath)
└─ 시설(Facility)
    ├─ 휴게시설(RestFacility)
    ├─ 운동시설(ExerciseFacility)
    ├─ 공원(Park)
    └─ 생활편의시설(Amenity)   ← 향후 하위 클래스 추가
```
- 행정구역(동) 클래스, 데이터 출처(Dataset) 클래스 포함.

### 7.3 모든 장소의 필수 속성
- 원본 이름(데이터셋 그대로), 좌표(경로는 선 형태), 주소(있으면),
- **중심으로부터의 거리(km)** — 경로는 중심에서 가장 가까운 지점까지의 거리(빌더가 기준을 문서화),
- 출처 데이터셋명, 데이터 기준일, 원본 레코드 식별자.

### 7.4 관계 (미리 계산해 저장)
- 근처에 있음(nearTo) — 거리(m) 포함, 기준 반경은 빌더 판단(예: 500m).
- 경로 위/옆에 있음(alongRoute) — 경로에서 일정 거리 이내 시설.
- 공원 안에 있음(locatedInPark).
- 행정동에 속함(inDistrict).
- 출처(fromDataset).
- 관계에 거리 값이 필요하므로 관계 자체를 객체로 표현하는 방식(예: 거리 노드) 등은 빌더 판단.

### 7.5 웹사이트와의 연결
- 원본은 지식 DB(.ttl) 하나. 빌드 스크립트가 .ttl에서 웹용 가벼운 파일(GeoJSON/JSON)을 자동 생성해 사이트가 읽는다.
- 데이터 처리 흐름: 공공데이터 파일 → 정제·좌표 변환·10km 필터·거리 계산 → .ttl 생성 → 웹용 파일 생성.

## 8. 데이터 출처 (후보 — 빌더가 실제 가능 여부 확인)

- 전국도시공원정보표준데이터 (공원, 일부 운동·휴게시설 정보)
- 전국자전거도로표준데이터
- 전국길관광정보표준데이터 / 걷기길 관련 표준데이터 (산책로)
- 화성시 체육시설·공공체육시설 현황 데이터
- 휴게시설(쉼터, 벤치, 그늘막 등) 관련 화성시/경기도 공공데이터
- 키 없이 다운로드 가능한 파일만 사용. 로그인이 필요한 다운로드는 사용자에게 직접 받아 달라고 요청.

## 9. 중심 좌표

- 주소: 경기도 화성시 동탄구 청계동 552. 좌표는 키 없는 방법(예: OSM Nominatim, 공개 자료)으로 확인 후 고정값으로 설정 파일에 기록하고, 확인 방법을 문서에 남긴다. 확인 결과를 사용자에게 보여 준다.

## 10. 설계자(Claude)가 정한 사항 — 사용자 확인 필요

1. **OpenStreetMap 데이터 보충:** 공공데이터를 우선 쓰고, 공공데이터에 없는 런닝코스·벤치·쉼터 등과 산책로/자전거도로의 선 모양은 OSM(Overpass, 키 불필요)에서 보충한다. 이름은 각 원본 이름 그대로, 장소마다 출처(공공데이터 데이터셋명 / OSM) 표시. OSM 라이선스(ODbL) 출처 표기.
2. **선 모양이 없는 경로:** OSM 길과 매칭되면 선으로, 매칭 실패 시 시작점 마커로 표시(삭제하지 않음).
3. **10km 범위:** 시 경계와 무관하게 중심 10km 안이면 포함(오산·용인·평택·수원 일부 포함). 전국 표준데이터 + OSM으로 덮고, 화성시 전용 데이터는 화성시 부분만 보강.
4. **10km 경계에 걸친 경로:** 자르지 않고 전체를 유지. 경로의 "중심에서 거리"는 가장 가까운 지점 기준이며 10km 미만이면 포함.
5. **같은 장소가 여러 데이터에 있을 때:** 하나의 개체로 합친다. 대표 이름은 우선순위 높은 공공데이터 원본 이름, 다른 원본 이름은 별칭(`skos:altLabel`)으로 모두 보존, 출처 링크 복수 기록.
6. **갱신 방식:** 이번에는 1회 수동 빌드. 다시 실행 가능한 스크립트로 만들어 나중에 데이터만 바꿔 재생성 가능. 개체 식별자(URI)는 원본 레코드 ID 기반으로 안정적으로 생성.

## 11. 빌더에게 맡기는 것

- 지도 라이브러리, 빌드 도구(Python 사용 가능: 3.13 / Node 22 설치됨), 폴더 구조.
- 온톨로지 네임스페이스·속성 이름(영문 식별자 + 한국어 라벨 `rdfs:label@ko`).
- 근처 판단 반경, 경로-시설 근접 기준.
- 마커 아이콘·색상, 세부 디자인.
- 배포 저장소 이름.
